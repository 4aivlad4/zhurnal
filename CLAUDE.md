# Журнал центра — правила для Claude

Бесплатное веб-приложение (PWA) — общий электронный журнал записи пациентов для семейного
реабилитационного центра. Записывает в основном мама, реже папа и дочь; телефоны Android
и моноблок в центре. Владелец проекта — не программист: код пишет Claude, владелец
проверяет результат на телефоне и принимает решения.

## 1. Общение — коротко (экономим токены)

- По-русски, простыми словами. Термины — только из словаря в `docs/owner-guide.md`
  или с пояснением в скобках.
- Не пересказывать ход работы, не показывать код и списки файлов, если об этом не просят.
- Отчёт в конце задачи — до 10 строк:
  - ✅ **Сделано** — 1–3 пункта: что изменилось для пользователя;
  - 👀 **Проверьте** — что открыть и нажать (если нужно);
  - ❓ **Нужно решение** — только если без владельца нельзя: варианты + рекомендация;
  - 🔗 ссылки: PR, сайт.
- Подробно — только там, где нужна реакция владельца. Остальное он спросит сам.
- Вопросы — пачкой в начале, а не по одному посреди работы. Мелкие решения
  принимать самому и записывать в `docs/decisions.md`.

## 2. Протокол сессии

Одна сессия — одна задача из плана.

| Владелец пишет | Что делать |
|---|---|
| «Следующая задача» / «Задача 1.4» | шаги 1–7 ниже |
| «Продолжи» | прочитать «Итог» текущей карточки (где остановились) → шаги 3–7 |
| «Статус» | 3–5 строк: где мы, что дальше, какие вопросы ждут владельца |
| «Сломалось: …» | воспроизвести → минимально починить → тест на этот случай → отчёт |
| «Хочу изменить: …» | мелочь — сделать сразу; крупное — строка в плане или новая карточка |
| «Откати последнее» | revert последнего слияния через PR → отчёт |

1. `docs/plan.md` → текущая задача (строка «Сейчас») или названная владельцем.
2. Её карточка в `docs/tasks/`. Читать **только** документы из раздела «Прочитать»,
   остальное — точечно, если понадобится. Карточка устарела — поправить и продолжить.
3. Делать только то, что в карточке. Всплыло лишнее — в «Хвосты» в `docs/plan.md`.
4. Проверить по `docs/code-rules.md` → «Проверки перед сдачей».
5. Заполнить «Итог» карточки, статус и строку «Сейчас» в `docs/plan.md`;
   новые решения — в `docs/decisions.md`.
6. Коммит → push → PR в `main`.
7. Отчёт (раздел 1).

Сессия всегда заканчивается PR с **рабочим** состоянием — даже если задача не закончена
(тогда в «Итоге»: где остановились и что осталось). Следующая сессия начинается с `main`.

## 3. Правила продукта — не нарушать

- Журнал только для своих: никакой онлайн-записи пациентов, никаких цен.
- В облаке нет персональных данных: имя как в тетради («Витя К.»), без фамилий, телефонов,
  диагнозов, дат рождения. Телефоны — только в памяти устройства.
- Наложение — предупреждение, а не запрет. Приложение ничего не отменяет само.
- Только бесплатные сервисы; платное — только с согласия владельца.
- Работает на Android (Chrome) и моноблоке, при медленном интернете и без него.
- Записать знакомого пациента — не дольше, чем ручкой в тетрадь.

## 4. Код и доставка — кратко

Подробно — `docs/code-rules.md` (прочитать перед тем, как писать код).

- Без сборки: JS-модули + Preact/htm из `app/vendor/`. Новые библиотеки — с согласия владельца.
- Firebase — только в `app/js/db-firebase.js`. Логика (время, наложения, разбор фраз) —
  в `app/js/logic/`, без интерфейса и сети, с тестами в `tests/`.
- Интерфейс по-русски, телефон — в первую очередь, крупные кнопки.
- В начале каждого файла — 1–3 строки по-русски: что он делает.
- Изменили что-то в `app/` — поднять версию в `app/js/version.js`.
- Работать в ветке, которую выдала сессия. PR в `main` — с описанием по-русски в 3–5 строк.
  Кто сливает — см. `docs/decisions.md` (В-2). После слияния сайт обновляется сам.

## 5. Карта документации

| Файл | Что внутри | Когда читать |
|---|---|---|
| `docs/plan.md` | план, статус, хвосты | в начале каждой сессии |
| `docs/tasks/*.md` | карточки задач | текущую задачу |
| `docs/project.md` | цели, принципы, границы, риски | сомнение «а надо ли это» |
| `docs/domain.md` | как устроен центр: люди, процедуры, аппараты | записи, наложения, фразы |
| `docs/architecture.md` | устройство приложения, файлы, публикация | задачи с кодом |
| `docs/data-model.md` | структура данных | задачи с данными |
| `docs/code-rules.md` | правила кода и проверок | перед написанием кода |
| `docs/decisions.md` | решения и открытые вопросы | когда нужно или принято решение |
| `docs/owner-guide.md` | инструкция для владельца, словарь | Claude — не нужно |
