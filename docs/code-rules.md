# Правила кода

Код пишет и сопровождает Claude, а проверяет не программист. Поэтому главное —
простота и предсказуемость.

## 1. Простота
- Самое простое решение, которое работает. Ничего «на будущее».
- Один файл — одна тема, до ~300 строк; функции короткие, имена говорящие.
- Без сборки: ES-модули в браузере как есть.
- Новые библиотеки — только с согласия владельца. Кладём в `app/vendor/`,
  версию и источник — в `app/vendor/README.md`. Никаких CDN во время работы приложения.

## 2. Слои
- `logic/` — чистые функции: на входе данные, на выходе результат. Без DOM, сети
  и `Date.now()` (текущее время передаётся параметром). Каждая функция — с тестами,
  включая крайние случаи: полночь, пустой день, 40 визитов, группа.
- Firebase — только в `db-firebase.js`. Демо — `db-demo.js` с тем же интерфейсом.
- Экраны (`ui/`) показывают состояние и вызывают действия `store.js`; логику не дублируют.

## 3. Данные
- Время — минуты от полуночи, даты — `ГГГГ-ММ-ДД`; вся арифметика времени —
  в `logic/time.js`.
- Правка — точечно по пути поля (`visits.<id>`), без перезаписи документа целиком.
- Нельзя: персональные данные в облаке (фамилии, телефоны, диагнозы). У полей заметок —
  подсказка «без фамилий, телефонов и диагнозов».
- Структура данных меняется только с миграцией и записью в `docs/decisions.md`.

## 4. Интерфейс
- Всё по-русски, без жаргона. Сообщения человеческие: «Нет связи — сохранится,
  когда появится интернет».
- Сначала телефон (ширина 360–412 px), потом моноблок.
- Кнопки и строки — от 48 px по высоте, текст — от 16 px (основной — 18 px),
  высокий контраст. Ничего не работает только по наведению мыши.
- Меньше экранов и шагов, разумные значения по умолчанию; обязательны только
  «кто» и «когда».
- Удаление — с подтверждением; наложение — предупреждение, не запрет; есть «Отменить».
- Не ждать сервер: показывать изменение сразу, синхронизировать в фоне.

## 5. Безопасность
- Не вставлять данные в HTML строкой (`innerHTML`) — только через шаблоны Preact/htm.
- В репозитории нет паролей и секретов. `config.js` Firebase публичный по устройству Firebase.
- Правила доступа — в `firebase/firestore.rules`; менять только вместе с владельцем
  (он вставляет их в консоль).

## 6. Имена и комментарии
- Переменные и функции — по-английски, понятно: `visitEnd`, `findConflicts`.
- В начале каждого файла — 1–3 строки по-русски: что делает файл.
- Комментарии — по-русски, объясняют «зачем», а не пересказывают код.

## 7. Версия
Любое изменение в `app/` → поднять `VERSION` в `app/js/version.js`: `0.<этап>.<номер>`
(например, `0.1.7`) и дату.

## 8. Проверки перед сдачей
1. `npm test` — все тесты зелёные; у новой логики есть тесты.
2. Менялся интерфейс → `npm run smoke`: нет ошибок в консоли. 1–2 скриншота экрана
   телефона (390×844) отправить владельцу файлом; в репозиторий не коммитить.
3. Сценарий из «Готово, когда» карточки пройден в демо-режиме (через Playwright).
4. Перечитать свой дифф: нет лишнего, отладочного кода, персональных данных.

## 9. Git
- Маленькие коммиты; сообщение по-русски, по сути: «День: переход по датам».
- Не коммитить скриншоты, временные файлы, `node_modules`.
- Ветка сессии → PR в `main`; описание — по-русски, 3–5 строк: что изменилось
  для пользователя.
- PR Claude сливает сам сжатием (squash): одна задача — один коммит в `main`,
  откат — revert этого коммита.

## 10. Совместимость
- Chrome на Android 10+ и браузер моноблока (уточняется в 0.3).
- Новые возможности браузера — только если они там поддерживаются; иначе — запасной вариант.
