# Как устроено приложение

## Схема
```
 Телефоны (Android, Chrome) ──┐                           ┌── Firebase Auth — вход
 Моноблок в центре (браузер) ─┴── приложение (PWA) ───────┤
                                  копия данных на         └── Firestore — данные,
                                  каждом устройстве            синхронизация

 Claude → ветка → PR → main → GitHub Actions (тесты) → хостинг сайта → телефоны
```

- **PWA** — сайт, который ставится иконкой и открывается как приложение. Файлы сайта
  хранятся в телефоне, поэтому он открывается и без интернета.
- **Firestore** — бесплатная облачная база Google (тариф Spark). Изменения за 1–2 секунды
  видны на всех устройствах; без интернета копятся на устройстве и уходят позже.
- **Хостинг** — GitHub Pages: репозиторий `4aivlad4/zhurnal` публичный,
  адрес сайта — https://4aivlad4.github.io/zhurnal/ (решение Р-13).

## Почему так
- Бесплатно и без своего сервера — нечего администрировать.
- Без сборки: что лежит в `app/`, то и работает — меньше мест, где может сломаться.
- Работа с базой — в одном файле: если Firebase станет недоступен из России,
  меняется только он.

## Файлы
```
app/                      сайт — публикуется целиком
  index.html              единственная страница
  manifest.webmanifest    описание PWA: имя, иконки, цвета
  sw.js                   сервис-воркер: хранит файлы в телефоне, обновляет
  css/  icons/
  vendor/                 сторонние библиотеки; версии и источники — vendor/README.md
  js/
    main.js               запуск: вход, выбор хранилища, экраны
    version.js            номер версии
    offline-files.js      список файлов для работы без интернета (его читает sw.js)
    config.js             публичные настройки Firebase (не секрет)
    seed-settings.js      начальные справочники (из docs/domain.md)
    store.js              состояние приложения и подписки экранов
    db.js                 единый интерфейс данных → db-firebase.js или db-demo.js
    db-firebase.js        ЕДИНСТВЕННОЕ место, где используется Firebase
    db-demo.js            демо-режим: выдуманные данные в браузере
    logic/                чистая логика, покрыта тестами
      time.js             минуты ↔ «15:30», даты, дни недели
      visits.js           цепочка процедур: время, сдвиг, перестановка
      conflicts.js        наложения
      attendance.js       явка, счётчик посещений, неотмеченные визиты
      repeats.js          повторы и копия недели
      parse.js            разбор фраз (этап 3)
    ui/                   экраны и элементы (Preact + htm)
tests/                    автотесты (*.test.js, node --test), смоук (Playwright), локальный сервер
firebase/firestore.rules  правила доступа — владелец вставляет в консоль Firebase
.github/workflows/        тесты на каждый PR; публикация сайта после тестов
.claude/hooks/            хук старта веб-сессии Claude: ставит зависимости для проверок
package.json              npm test · npm run serve · npm run smoke
```
Файлы появляются по мере задач. Структура — ориентир; меняем её осознанно
и записываем сюда.

## Слои
```
ui/ ──► store.js ──► db.js ──► db-firebase.js | db-demo.js
 └──────────┴──────► logic/    (logic ни от чего не зависит)
```
- Экраны не обращаются к базе напрямую — только через `store.js`.
- Интерфейс `db.js` (набросок, уточняется в 1.1 и фиксируется здесь):
  `signIn`, `signOut`, `onSettings(cb)`, `onPatients(cb)`, `onDay(date, cb)`,
  `savePatient(p)`, `saveVisit(date, v)`, `deleteVisit(date, id)`, `moveVisit(from, to, v)`,
  `saveBlock(date, b)`, `deleteBlock(date, id)`, `exportAll()`.

## Хранилище
- Firestore с офлайн-кэшем (`persistentLocalCache`, несколько вкладок).
- Один документ на день, один на всех пациентов, один на справочники
  (`docs/data-model.md`). Открыть приложение ≈ 5 чтений; бесплатно — 50 000 в день.
- **Демо-режим** (`?demo` в адресе или кнопка на экране входа): ≈60 выдуманных пациентов,
  ≈30 визитов в день; в Firebase ничего не пишет. Нужен для показа семье, обучения
  и автопроверок.

## Вход и доступ
- Firebase Auth, «почта» + пароль. Почты выдуманные (`mama@example.com`) —
  письма никуда не уходят. Пользователей заводит владелец в консоли;
  самостоятельная регистрация выключена.
- Экран входа: крупные кнопки «Мама / Папа / Дочь / Другой» + пароль. Один раз —
  дальше устройство помнит.
- Правила Firestore пускают только перечисленных пользователей (по UID) —
  `firebase/firestore.rules`.
- `apiKey` в `config.js` — не секрет: так устроен Firebase, данные защищают правила.
  Дополнительно ключ ограничивается адресом сайта (задача 0.2).

## Справочники
Люди, процедуры, аппараты, часы работы, синонимы — документ `meta/settings`.
Начальные значения — `app/js/seed-settings.js`. Изменение — через Claude: правка seed
и `seedVersion` → приложение обновит справочник при запуске. Экран редактирования —
позже, если понадобится.

## Обновления на телефонах
- Сервис-воркер хранит файлы сайта; имя кэша содержит версию из `version.js`.
- Новая версия скачивается в фоне и включается при следующем открытии.
  В «Ещё» — номер версии и кнопка «Обновить сейчас».

## Публикация
Слияние в `main` → GitHub Actions: `npm test` → публикация `app/` (1–2 минуты).
Тесты не прошли — сайт не меняется.

## Проверки
- `npm test` — тесты логики на встроенном тест-раннере Node, без зависимостей.
- `npm run smoke` — Playwright открывает приложение в демо-режиме в окне размером
  с телефон (390×844): нет ошибок в консоли, скриншоты основных экранов; журнал открывается
  без интернета, новая версия видна со второго открытия.
  Playwright нужен только для проверок, на сайт не попадает.

## Запасной план хранилища
Если Firebase из России недоступен:
1. Yandex Cloud — serverless-база YDB и функции: есть бесплатный уровень,
   нужна привязка карты.
2. Недорогой сервер в РФ с PocketBase — платно, несколько сотен рублей в месяц.

В обоих случаях меняется только `db-firebase.js` (появляется файл вместо него);
экраны и логика не трогаются.
