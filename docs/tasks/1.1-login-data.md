# 1.1 Вход, данные, демо-режим

Этап 1 · Размер M · Статус ⬜

## Зачем
Фундамент журнала: вход один раз, данные синхронизируются между устройствами
и сохраняются без интернета. Демо-режим с выдуманными данными — для показа семье
и автопроверок.

## Прочитать
- `docs/architecture.md` — «Слои», «Хранилище», «Вход и доступ», «Справочники»
- `docs/data-model.md` — целиком
- `docs/code-rules.md` — разделы 2, 3, 4

## Сделать
1. `db.js` — единый интерфейс данных. Итоговый список функций записать
   в `docs/architecture.md` → «Слои».
2. `db-firebase.js`: подписки на `meta/settings`, `meta/patients`, `days/{дата}`;
   точечные записи; перенос между днями — одной пакетной записью; офлайн-кэш.
3. `db-demo.js` — тот же интерфейс на выдуманных данных: ≈60 пациентов, ≈30 визитов в день
   на ±7 дней, пара групп, пара записей «карандашом». Хранение — память + localStorage.
4. Первый запуск: нет `meta/settings` — записать из `seed-settings.js`;
   вырос `seedVersion` — обновить.
5. `logic/time.js` + тесты: минуты ↔ «15:30», даты, сдвиг дней, день недели.
6. `store.js`: текущая дата, кто вошёл, данные, подписка экранов на изменения.
7. Экран входа вместо временного из 0.2: «Мама / Папа / Дочь / Другой» + пароль;
   кнопка «Демо-режим»; вход запоминается.
8. Навигация: нижняя панель «День · Пациенты · Ещё». В «Ещё»: кто вошёл, версия,
   «Обновить сейчас», «Выйти», режим (демо или настоящий).
9. Индикатор связи: «Нет связи — изменения сохранятся позже».

## Не делать
- Содержимое экранов «День» и «Пациенты» — пока заглушки со счётчиками.

## Готово, когда
- [ ] вход один раз; после перезапуска пароль не нужен
- [ ] демо-режим показывает выдуманные данные (счётчики на заглушках)
- [ ] изменение на одном устройстве появляется на другом за 1–2 с (тестовая кнопка в «Ещё»)
- [ ] в авиарежиме изменение сохраняется и уходит, когда появится сеть
- [ ] тесты `logic/time.js` и смоук зелёные
